# GPTI 内容人工审稿清单

日期：2026-05-27

适用版本：`content-2026-05-28-gpti-title-clean-a`

范围：当前已部署的 24 题、16 型结果、隐藏特质和分享文案。

本文件是人工审稿材料，不修改线上内容，不递增 `contentVersion`。如果审稿后需要改题目、选项、结果解释或分享文案，必须新开内容版本。

## 1. 审稿结论格式

建议内容负责人按三类给结论：

| 结论 | 含义 | 后续动作 |
| --- | --- | --- |
| 通过 | 可作为 5 月 31 日兜底首发内容 | 不改代码 |
| 低风险修 | 错字、轻微语气、个别措辞，不改变题意或结果理解 | 可做补丁内容版本 |
| 必须修 | 影响用户选择、结果理解、分享意愿，或存在明显 IP/冒犯/误导风险 | 必须递增 `contentVersion` 并完整回归 |

## 2. 全局审稿红线

- 用户可见文案不出现 `ATRB` / `ATRC` 等内部 type code。
- 用户可见文案不出现 `keywords`、`poles`、`pole`、`type code` 等内部字段名。
- 不出现 `MBTI`、`INTJ`、`ENFP` 等外部人格体系口径。
- 不把隐藏特质写得比 16 型主结果更像主结论。
- 不把玩家偏好写成心理诊断、现实人格定性或现实群体标签。
- 不使用未经确认的真实 IP、真实人物、品牌或明显可识别梗作为关键卖点。
- 分享文案不能承诺“一键分享到某平台”，只能提示保存图片、复制文案或系统分享。

技术测试已覆盖 16 型完整性、字段长度、公开字段、内部字段不泄露和文案差异化。人工审稿重点是“是否像一个可分享的结果”。

| Type | 结果名 | 初筛结论 | 人工审稿问题 |
| --- | --- | --- | --- |

| `ATRC` | 渗透者 | 可用 | “不走正门”表达好；确认不要暗示现实负面行为 |
| `ATWB` | 开拓者 | 可用 | 与 `AIWB`、`PTWB`、`PIWB` 都有探索感，需要确认差异足够 |
| `ATWC` | 账本侠 | 可用 | “算性价比”好懂；确认“账本侠”是否够游戏职业感 |
| `AIRB` | 羁绊黏合剂 | 可用 | 名称略口语，确认是否需要更像职业称号 |
| `AIRC` | 幕后军师 | 可用 | 与 `PTWC` 都偏理性稳健，确认差异 |
| `AIWB` | 全知探索者 | 可用 | “全知”气质较强，确认是否过度拔高 |
| `AIWC` | 天平守护者 | 可用 | 秩序、仪式感表达稳定；确认不显得说教 |
| `PTRB` | 幸存者 | 可用 | “残血嘴硬”好记；确认不要太消极 |

## 6. 内容版本决策

| 审稿结果 | 是否递增 `contentVersion` | 说明 |
| --- | --- | --- |
| 全部通过 | 否 | 保持 `content-2026-05-28-gpti-title-clean-a` |
| 只补资产 | 通常否 | 头像、徽章、OG 图不改变结果理解时可不递增 |
| 低风险错字修 | 是 | 影响用户阅读，建议补丁版本，例如 `content-2026-05-28-gpti-full-copy-b` |
| 改题目/选项 | 是 | 会影响用户选择和漏斗解释 |
| 改结果/分享文案 | 是 | 会影响结果理解和分享意愿 |
| 改评分 `poles` | 是，且必须单独确认 | 会影响 16 型分布，不建议 5 月 31 日前做 |

## 7. 建议审稿流程

1. 内容负责人先按本文第 3-5 节打结论。
2. 只要出现“必须修”，开发侧先确认是否影响题意、评分、结果体系或分享理解。
3. 若要改内容，新开内容版本和 feature 分支，先写失败测试锁定新文案和版本号，再实现。
4. 修改后至少运行：
   - `node --test .\tests\*.test.mjs`
   - `npm run build`
   - 敏感信息扫描
   - 移动端 24 题和分享图冒烟
5. 部署时只上传 `dist/` 到 CloudBase 静态托管，不改后端配置。
