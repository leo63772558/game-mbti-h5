# GPTI 内容输入模板与校验规则

本文用于支持文案同学继续完善 GPTI 玩家人格体系内容，并帮助开发侧低风险接入结构化题库、标准 16 型结果和隐藏特质。

当前 GPTI 内容仍在迭代中。开发侧不应直接从长文中手工复制到代码，应优先要求文案源整理为本文模板。

## 1. 当前技术建议

GPTI 第一版建议采用：

- 标准 16 型作为唯一主结果。
- 隐藏人格已收敛为“隐藏特质 / 稀有变体”，附加展示，不覆盖主结果。
- 四选项题库。
- 八极分值决定主类型。
- 关键词用于解释、校验、埋点 payload 和隐藏特质触发；第一阶段不新增关键词热度看板。
- 当前开发接入版本为 `content-2026-05-28-gpti-title-clean-a`；本版本在 `content-2026-05-27-gpti-full-copy-a` 基础上清理题目标题开头编辑分隔符和第 18 题编辑标记，不改选项、关键词、评分或结果文案。
- GPTI 结构与旧 `content-2026-05-21` 样稿结构不可混算；复盘时需按 `contentVersion` 分开筛选。

## 3. 关键词白名单

当前关键词库包含 42 个关键词。2026-05-26 试用版为同步 docx 前 18 题关键词，新增了“刺激、压线、对冲、捡漏、整活、氛围组、清空、目押、赌狗、面板”。

| 分组 | 关键词 |
|---|---|
| 行动轴 | 莽、上头、刺激、预判、复盘、稳健、效率、速通、嘴硬、压线、对冲、赌狗 |
| 系统轴 | 机制、公式、漏洞、背板、推理、拆解、控场、冷门、目押、面板 |
| 世界轴 | 探索、支线、开图、漫游、收集、捡漏、氛围、整活、氛围组、细节、沉浸、清空 |
| 情绪/角色轴 | 剧情、羁绊、共鸣、审美、仪式感、怀旧、情绪、白月光 |

如需新增关键词，应先更新关键词库、题库校验和结果映射说明。不要在题目选项中临时加入未登记关键词。

## 4. 八极分值

每个选项可给以下极向加分：

| 极向 | 含义 |
|---|---|
| `A` | 主动发起 |
| `P` | 被动观察 |
| `T` | 行动任务 |
| `I` | 交互关系 |
| `R` | 人物成长 |
| `W` | 世界探索 |
| `B` | 冒险押注 |
| `C` | 稳健控制 |

建议每个选项最多给 1 到 3 个极向加分，避免一个选项过度复杂。

推荐分值：

| 分值 | 用法 |
|---:|---|
| `1` | 弱倾向 |
| `2` | 主倾向 |
| `3` | 极强倾向，仅用于非常明确的选项 |

不建议使用负分。对立倾向应通过给另一极加正分表达。

## 5. 题库输入模板

建议在腾讯文档中按表格维护。字段如下：

| 字段 | 必填 | 说明 |
|---|---:|---|
| `id` | 是 | 题目 ID，例如 `q01` |
| `chapter` | 是 | 章节编号 |
| `chapterTitle` | 是 | 章节标题 |
| `chapterFeedback` | 是 | 完成本章节后的反馈文案 |
| `title` | 是 | 用户看到的题干 |
| `optionA.text` | 是 | A 选项文案，不是 A 极向 |
| `optionA.keywords` | 是 | 逗号分隔，必须来自关键词白名单 |
| `optionA.poles` | 是 | 例如 `A:2,T:2,B:1` |
| `optionB.text` | 是 | B 选项文案 |
| `optionB.keywords` | 是 | 逗号分隔 |
| `optionB.poles` | 是 | 极向分值 |
| `optionC.text` | 是 | C 选项文案 |
| `optionC.keywords` | 是 | 逗号分隔 |
| `optionC.poles` | 是 | 极向分值 |
| `optionD.text` | 是 | D 选项文案 |
| `optionD.keywords` | 是 | 逗号分隔 |
| `optionD.poles` | 是 | 极向分值 |
| `status` | 是 | 草稿 / 待审 / 已确认 |
| `notes` | 否 | 争议、风险或待确认点 |

结构化代码示例：

```js
{
  id: 'q01',
  chapter: 1,
  title: '你伫立在一座阴森的城堡大门前，上面写着：“只有不想进去的人才能进去。”你会？',
  options: [
    {
      id: 'a',
      text: '拿起斧头就往门上劈。谜语人给我滚。',
      keywords: ['莽', '效率', '速通'],
      poles: { A: 2, T: 2, B: 1 },
    },
    {
      id: 'b',
      text: '绕城堡三周，找找有什么开门的线索。',
      keywords: ['稳健', '推理', '细节'],
      poles: { P: 1, W: 1, C: 2 },
    },
    {
      id: 'c',
      text: '开启鬼脑：谁说一定要从门这边进？试着找地形卡进去。',
      keywords: ['机制', '漏洞', '冷门'],
      poles: { A: 1, T: 1, B: 2 },
    },
    {
      id: 'd',
      text: '疑问：这则留言背后有什么故事？城主为什么这么说？',
      keywords: ['预判', '剧情', '沉浸'],
      poles: { P: 1, I: 1, W: 2 },
    },
  ],
}
```

## 6. 结果输入模板

| 字段 | 必填 | 建议长度 | 说明 |
|---|---:|---:|---|
| `type` | 是 | 4 | GPTI key，例如 `ATRB` |
| `name` | 是 | 4-8 字 | 主结果名 |
| `alias` | 否 | 1-3 个 | 备选外号数组 |
| `identity` | 是 | 12 字内 | 用户可见身份 |
| `headline` | 是 | 36 字内 | 首屏金句 |
| `tags` | 是 | 3-5 个 | 结果标签，尽量来自关键词库 |
| `summary` | 是 | 60 字内 | 首屏短解释 |
| `behaviorFragments` | 是 | 3-5 条 | 行为碎片 |
| `charges` | 是 | 2-3 条 | 游戏行为罪状，保持轻自嘲 |
| `talent` | 是 | 36 字内 | 隐藏天赋 |
| `weakness` | 是 | 36 字内 | 致命弱点 |
| `bestPartners` | 是 | 1-2 个 | 标准 type 数组 |
| `nemesis` | 是 | 1 个 | 标准 type 数组 |
| `shareCTA` | 是 | 28 字内 | 分享行动文案 |
| `longCopy` | 否 | 不限 | 展开区或内部长文，不进分享图 |
| `status` | 是 | - | 草稿 / 待审 / 已确认 |
| `notes` | 否 | - | 风险、争议、待补内容 |

结构化代码示例：

```js
{
  type: 'ATRB',
  name: '狂战士',
  alias: ['莽穿肠', '人形推土机'],
  identity: '高风险开团位',
  headline: '你的战术很简单：看见敌人，先冲再说。',
  tags: ['莽', '上头', '速通', '嘴硬'],
  summary: '你追求直接、刺激和高风险回报，讨厌拖泥带水。',
  behaviorFragments: [
    '有门必踹，有窗必翻。',
    '语音里最常说：能杀、我的、下一把。',
    '残血时觉得自己终于进入状态。',
  ],
  charges: [
    '战术约等于零，但气势通常很满。',
    '资源管理灾难，高级道具经常打在小怪身上。',
  ],
  talent: '极限局里反应快得离谱。',
  weakness: '容易把撤退打成二次开团。',
  bestPartners: ['ATRC'],
  nemesis: ['PIWC'],
  shareCTA: '发给那个每次开团都喊跟我上的人。',
  longCopy: '可选长文，后续作为展开阅读或运营素材。',
}
```

## 7. 隐藏特质输入模板

隐藏特质不是主结果，不应替代标准 16 型。建议第一版最多准备 3 到 5 个。

| 字段 | 必填 | 说明 |
|---|---:|---|
| `id` | 是 | 稳定 id，例如 `scripted_gambler` |
| `name` | 是 | 用户可见名称 |
| `priority` | 是 | 数字越小优先级越高 |
| `triggerType` | 是 | `keyword_combo` / `single_pole_spike` / `dual_high_conflict` |
| `conditions` | 是 | 结构化触发条件 |
| `headline` | 是 | 一句话说明 |
| `copy` | 是 | 短解释 |
| `notes` | 否 | 争议或验证说明 |

示例：

```js
{
  id: 'scripted_gambler',
  name: '人形脚本外挂',
  priority: 10,
  triggerType: 'keyword_combo',
  conditions: {
    keywordsAll: ['背板'],
    polesMin: { B: 4, C: 4 },
  },
  headline: '看起来像赌，其实全是练过。',
  copy: '你把高风险操作练成了肌肉记忆，别人以为你在押命，你只是在执行脚本。',
}
```

## 8. 校验规则

开发接入前至少需要通过以下校验：

- 题目 ID 不重复。
- 每题正好 4 个选项。
- 每个选项 `text`、`keywords`、`poles` 不为空。
- 所有关键词都在白名单内。
- 所有 pole key 都在 `A/P/T/I/R/W/B/C` 内。
- pole 分值为正整数，建议范围 `1` 到 `3`。
- 16 个标准结果完整。
- 结果 `type` 不重复。
- `bestPartners` 和 `nemesis` 引用的 type 必须存在。
- 用户可见文案不直接暴露内部 type code；当前确认口径是不在用户端展示 `ATRB` / `ATRC` 等内部编码。
- 结果页首屏字段和分享图字段不明显超出移动端展示范围。
- 高风险词、攻击性词、现实群体标签、可能侵权的真实 IP 表达需要人工复审。

## 9. 给文案侧的当前反馈

- 当前关键词库和 16 型映射已经有较好基础，建议优先稳定关键词白名单和 type 列表。
- 当前结果长文适合做素材库，但 H5 首屏和分享图需要压缩成短字段。
- 当前第一版按 24 题设计；后续若改变题量，需要同步更新 spec、测试、漏斗和 dashboard 说明。
- 四选项题目需要补充结构化 `poles`，不能只给关键词。
- 隐藏人格已作为第二层“隐藏特质”处理，第一版不要让它覆盖标准主结果。

## 10. 已确认事项与待确认问题

已确认：

1. 正式第一版保持 24 题。
2. 用户端默认不展示 `ATRB` 这类 code，仅展示中文结果名、身份、标签和短解释。
3. 第一版展示隐藏特质，但隐藏特质不覆盖标准主结果。
4. CloudBase rollup / dashboard 第一阶段不新增关键词热度、四轴分布或隐藏特质分布。

待确认：

1. 结果页是否需要展开长文，还是先只展示短版结果。
2. 推荐作品和真实 IP 角色是否进入用户端，还是仅内部参考。
