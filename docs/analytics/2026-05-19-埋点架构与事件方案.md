# 异界开局人格测试 H5 埋点架构与事件方案

## 1. 目标

本方案用于补齐“异界开局人格测试 / 游戏人格 H5”的数据闭环，服务 pre 阶段展示和后续优化。

核心要回答 4 个问题：

1. 有多少人进入活动、从哪些渠道进入。
2. 有多少人开始答题、在哪里流失。
3. 有多少人完成测试、结果是否让用户愿意分享。
4. 不同设备、浏览器、渠道下是否存在明显体验问题。

当前 H5 继续保持纯静态形态，不引入 React / Vue / Next / Vite，不改业务主流程。埋点只作为一层轻量数据能力接入。

## 2. 架构决策

### 2.1 数据接收端

采用：

```text
CloudBase HTTP 云函数 + CloudBase 数据库
```

前端仍是纯静态 H5，用户行为通过 HTTP 请求上报到 CloudBase 云函数，云函数做基础校验后写入数据库。

说明：

- 纯静态 H5 本身不能把数据长期保存到线上数据库。
- 纯静态 H5 可以通过 `sendBeacon` 或 `fetch` 把事件发给服务端。
- 这里的云函数只做埋点收集，不承载业务逻辑，不影响 H5 静态部署架构。
- pre 阶段预计数据量很小，优先使用 CloudBase 免费体验额度或低量按量计费；上线前需在控制台确认当前环境套餐、免费额度和是否开启按量计费。埋点实现必须设置批量上报、事件白名单和单会话上限，避免异常消耗。

### 2.2 数据粒度

采用：

```text
事件明细级
```

即每次页面曝光、答题、完成、分享点击都写入一条事件明细，而不是只写汇总数。

原因：

- pre 需要分析“第几题流失最严重”。
- 需要按渠道、设备、浏览器拆分。
- 后续可从明细数据聚合任意漏斗，不被早期汇总口径限制。

### 2.3 匿名用户标识

采用：

```text
anon_id + session_id
```

- `anon_id`：随机 UUID，写入 `localStorage`，用于估算 UV 和复访。
- `session_id`：随机 UUID，写入 `sessionStorage`，用于一次访问会话分析。

隐私边界：

- 不采集姓名、手机号、微信号、QQ 号、精确地理位置。
- 不采集真实个人身份。
- `anon_id` 只是随机匿名 ID，不应与现实身份绑定。

## 3. 总体数据流

```text
用户行为
  -> app.mjs 调用 track(eventName, payload)
  -> analytics.mjs 补公共字段
  -> 写入浏览器本地队列
  -> navigator.sendBeacon(endpoint, body)
  -> sendBeacon 不可用时 fetch(endpoint, { keepalive: true })
  -> CloudBase HTTP 云函数
  -> 校验事件名、字段大小、批量条数
  -> 写入 analytics_events
  -> 导出 CSV 或跑聚合脚本
  -> pre 展示核心指标和漏斗
```

## 4. 前端模块设计

新增文件：

```text
src/analytics.mjs
```

职责：

- 生成和读取 `anon_id`、`session_id`。
- 补齐事件公共字段。
- 管理本地事件队列。
- 批量上报事件。
- 失败时保留队列并下次重试。
- 在本地开发或未配置 endpoint 时继续输出 console，避免影响调试。

建议暴露 API：

```js
initAnalytics({
  endpoint,
  appVersion,
  contentVersion,
  channel,
  debug,
});

track(eventName, payload);

flushAnalytics();
```

`app.mjs` 只负责在关键行为点调用 `track()`，不关心请求、重试、公共字段和存储细节。

## 5. 上报策略

### 5.1 批量上报

事件先进入本地队列，满足任一条件时上报：

- 队列达到 10 条。
- 距上次 flush 超过 5 秒。
- 页面进入后台或关闭。
- 测试完成、结果页曝光、分享行为触发。

### 5.2 上报方式

优先：

```js
navigator.sendBeacon(endpoint, blob)
```

fallback：

```js
fetch(endpoint, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(body),
  keepalive: true,
});
```

### 5.3 失败处理

- 上报失败不阻塞答题流程。
- 网络失败时事件保留在本地队列。
- 队列最大保留 100 条，超过后丢弃最旧事件，避免 localStorage 过大。
- 单条 payload 做大小限制，避免异常字段撑爆请求。

## 6. 公共字段

每条事件都带以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `event_id` | string | UUID，用于去重 |
| `event_name` | string | 事件名 |
| `at` | string | 前端触发时间，ISO 8601 |
| `session_id` | string | 本次访问会话 ID |
| `anon_id` | string | 匿名用户 ID |
| `channel` | string | 当前 `h5_channel` |
| `page_id` | string | 当前页面，如 `home`、`quiz`、`result` |
| `host` | string | 当前页面 `location.host`，用于区分 Vercel、CloudBase 默认域名、自定义域名和本地预览 |
| `origin` | string | 当前页面 `location.origin`，用于按部署来源追溯数据 |
| `path` | string | `location.pathname` |
| `query` | string | `location.search`，用于排查渠道参数 |
| `referrer` | string | `document.referrer` |
| `device_type` | string | `mobile` / `desktop` |
| `viewport_width` | number | 可视区宽 |
| `viewport_height` | number | 可视区高 |
| `user_agent` | string | 浏览器 UA |
| `browser_hint` | string | 粗略识别 `wechat` / `qq` / `safari` / `chrome` / `other` |
| `app_version` | string | 当前 H5 版本，可用短 commit 或手动版本 |
| `content_version` | string | 当前题库和结果文案版本，当前 GPTI 版本为 `content-2026-05-28-gpti-title-clean-a` |
| `payload` | object | 事件业务字段 |

说明：

- `host` / `origin` 是部署来源字段，不是用户身份字段。
- 本地 `file://` 场景下 `origin` 可能为空；正式建议通过本地静态服务器预览。
- 只要 `index.html` 包含当前 `GH_ANALYTICS_CONFIG.endpoint`，Vercel、CloudBase 静态站和本地预览都会上报到同一个 CloudBase endpoint。
- P0 只在明细事件中保留 `host`、`origin`、`content_version`；Phase 5B 已把 `analytics_source_daily` 升级为来源看板快照表，有 `host` / `contentVersion` 筛选时，summary、funnel、questions、results、share 均按同一来源/版本口径展示。
- 当前预览入口为 Vercel；CloudBase 默认静态托管域名只用于技术排查。正式用户入口等待腾讯光核提供已备案正式域名后接入。
- 当前 GPTI 版本使用 `content-2026-05-28-gpti-title-clean-a`。旧 `content-2026-05-21` 只代表历史样稿和 legacy fixture，不能和 GPTI 数据混算。

## 7. 事件清单

### 7.1 入口与开始

| 事件 | 触发时机 | payload | 关键指标 |
|---|---|---|---|
| `page_view` | 页面渲染 | `page_id` | PV、入口页曝光 |
| `test_start` | 点击开始/继续冒险 | `is_resume`, `answered_count` | 首页开始率、继续率 |
| `rules_view` | 查看规则页 | `from_page` | 规则点击率 |

### 7.2 答题过程

| 事件 | 触发时机 | payload | 关键指标 |
|---|---|---|---|
| `question_view` | 题目展示 | `question_id`, `question_index`, `chapter`, `option_count` | 每题曝光、题目漏斗 |
| `question_answer` | 用户选择答案 | `question_id`, `question_index`, `chapter`, `option_id`, `keywords`, `poles`, `time_spent_ms`, `is_change` | 单题耗时、犹豫点、答案分布 |
| `chapter_complete` | 每 6 题章节完成页展示 | `chapter`, `answered_count`, `duration_ms` | 章节漏斗 |
| `test_complete` | 24 题完成并进入生成 | `duration_ms`, `result_type_internal`, `result_name`, `hidden_trait_id`, `hidden_trait_name`, `confidence_avg`, `low_confidence_count` | 完成率、完成时长、结果分布 |

说明：

- `result_type_internal` 属于内部分析字段，只写入数据和内部看板，不展示给用户端。
- 当前 GPTI `question_answer` 不再发送旧 `dimension`、`score`、`score_*`。这些字段只在旧 `content-2026-05-21` 历史数据和 legacy 测试 fixture 中出现。
- `time_spent_ms` 通过题目展示时间和答题时间差计算。
- `is_change` 用于区分首次作答和返回上一题后改答案。

### 7.3 结果与分享

| 事件 | 触发时机 | payload | 关键指标 |
|---|---|---|---|
| `result_view` | 结果页展示 | `result_type_internal`, `result_name`, `hidden_trait_id`, `hidden_trait_name`, `archive_code`, `confidence_avg` | 结果页曝光 |
| `generate_share_image_click` | 点击生成分享图 | `result_type_internal`, `result_name`, `hidden_trait_id`, `image_type` | 分享意图 |
| `share_overlay_view` | 分享弹层展示 | `result_name`, `hidden_trait_id`, `image_type` | 弹层曝光 |
| `save_image_click` | 点击保存图片 | `result_type_internal`, `result_name`, `hidden_trait_id`, `image_type` | 保存图意图 |
| `copy_share_click` | 复制分享文案 | `result_type_internal`, `result_name` | 文案传播意图 |
| `copy_test_link_click` | 复制测试链接 | `channel`, `share_url_has_channel` | 拉人回流意图 |
| `platform_share_click` | 点击平台文案 | `platform`, `result_name` | 平台偏好 |
| `restart_click` | 点击重新测试 | `from_result_name`, `answered_count` | 重玩意愿 |

### 7.4 错误与稳定性

| 事件 | 触发时机 | payload | 用途 |
|---|---|---|---|
| `error_show` | 显示错误或兜底提示 | `error_type`, `message`, `page_id` | 定位体验问题 |
| `share_image_fallback` | Canvas 失败走 SVG fallback | `reason` | 图片生成稳定性 |
| `copy_failed` | Clipboard 和 execCommand 都失败 | `target` | 复制能力兼容性 |

## 8. 核心指标口径

### 8.1 北极星指标

```text
有效完成并产生分享意图的会话数
```

定义：

```text
unique session_id where test_complete happened
AND at least one of:
- generate_share_image_click
- save_image_click
- copy_share_click
- copy_test_link_click
- platform_share_click
```

### 8.2 pre 必看指标

| 模块 | 指标 | 公式 |
|---|---|---|
| 参与 | UV | unique `anon_id` |
| 参与 | 会话数 | unique `session_id` |
| 参与 | 开始率 | `test_start / home page_view` |
| 流失 | 完成率 | `test_complete / test_start` |
| 流失 | 每题保留率 | `question_view(qN+1) / question_view(qN)` |
| 流失 | 章节完成率 | `chapter_complete / test_start` |
| 体验 | 平均完成时长 | avg `test_complete.duration_ms` |
| 体验 | 单题平均耗时 | avg `question_answer.time_spent_ms` by question |
| 结果 | 结果类型分布 | count `test_complete` by `result_name` |
| 分享 | 分享意图率 | share intent sessions / `result_view` sessions |
| 分享 | 保存图片率 | `save_image_click / result_view` |
| 分享 | 平台偏好 | count `platform_share_click` by `platform` |
| 渠道 | 渠道完成率 | `test_complete / test_start` by `channel` |
| 渠道 | 渠道分享率 | share intent sessions / result sessions by `channel` |

| `event_name` | string | 事件名 |
| `at` | date/string | 前端触发时间 |
| `received_at` | date | 服务端接收时间 |
| `session_id` | string | 会话 ID |
| `anon_id` | string | 匿名用户 ID |
| `channel` | string | 渠道 |
| `page_id` | string | 页面 |
| `device_type` | string | 设备类型 |
| `browser_hint` | string | 浏览器粗分 |
| `viewport_width` | number | 视口宽 |
| `viewport_height` | number | 视口高 |

| `origin` | string | 页面协议、域名和端口 |
| `path` | string | 路径 |
| `query` | string | 查询参数 |

## 10. CloudBase 云函数设计

函数名建议：

```text
analytics_collect
```

HTTP 请求：

```http
POST /analytics/collect
Content-Type: application/json
```

请求体：

```json
{
  "events": [
    {
      "event_id": "uuid",
      "event_name": "question_answer",
      "at": "2026-05-19T12:00:00.000Z",
      "session_id": "uuid",
      "anon_id": "uuid",
      "channel": "wechat_group",
      "page_id": "quiz",
      "host": "demo-phi-pearl.vercel.app",
      "origin": "https://demo-phi-pearl.vercel.app",
      "content_version": "content-2026-05-28-gpti-title-clean-a",
      "payload": {
        "question_id": "q07",
        "question_index": 7,
        "chapter": 2,
        "option_id": "a",
        "keywords": ["莽", "效率", "速通"],
        "poles": { "A": 2, "T": 2, "B": 1 },
        "time_spent_ms": 4200,
        "is_change": false
      }
    }
  ]
}
```

云函数校验：

- 只接受 `POST`。
- 单次最多 20 条事件。
- `event_name` 必须在白名单内。
- `event_id`、`session_id`、`anon_id` 必须存在。
- 单条事件序列化后建议不超过 8KB。
- `payload` 只允许对象，不允许超大字符串。
- 写库失败时返回 500，前端保留队列下次重试。

返回：

```json
{
  "ok": true,
  "accepted": 3
}
```

## 11. 隐私与合规边界

不采集：

- 姓名。
- 手机号。
- 微信号 / QQ 号。
- 精确地理位置。
- 学号、身份证号等真实身份信息。
- 用户输入的自由文本。

允许采集：

- 匿名随机 ID。
- 会话 ID。
- 渠道参数。
- 页面和按钮行为。
- 设备和浏览器粗略信息。
- 当前 GPTI 答题选项 id、关键词、八极 `poles` 和内部分析字段。

用户端页面、答题选项、分享图和平台分享文案不展示 `ATRB` / `ATRC` 等内部 type code，也不展示关键词或 pole；这些字段仅用于计算、埋点和内部看板。

页面规则说明中可保持当前“本地计算，不上传敏感数据”的表达。若正式接入埋点，建议补一句：

```text
我们会记录匿名访问、答题进度和分享点击等行为数据，用于活动效果统计和体验优化，不采集真实身份信息。
```

## 12. 实施步骤

### P0：最小可用数据闭环

1. 新增 `src/analytics.mjs`。
2. 将 `app.mjs` 中现有 `track()` 替换为 `analytics.mjs` 的 `track()`。
3. 补 `anon_id`、`session_id`、公共字段。
4. 补 `time_spent_ms`、`duration_ms`。
5. 新增 CloudBase HTTP 云函数 `analytics_collect`。
6. 新增数据库集合 `analytics_events`。
7. 本地和线上各跑一遍完整 24 题，确认事件入库。
8. 导出 CSV，手动算出开始率、完成率、分享意图率。

历史说明：以上 P0 事项已在旧样稿阶段落地。当前 GPTI 迁移阶段不新增 CloudBase 集合或配置，只更新前端 payload 与兼容测试。

### P1：pre 分析增强

1. 增加聚合脚本或导出模板。
2. 生成渠道漏斗、题目漏斗、分享漏斗。
3. 增加 `error_show`、`copy_failed`、`share_image_fallback`。
4. 把 `app_version` 固定到当前提交短 hash 或手动版本号。

### P2：后续增强

1. 结果稀有度统计。
2. 更细的分享回流归因。
3. 简单 dashboard。
4. 首页文案或题目节奏 A/B 测试。

## 13. 验收标准

前端：

- 无 endpoint 时，H5 正常运行，只输出 console。
- 有 endpoint 时，事件能入库。
- 上报失败不影响答题、结果页、分享图。
- 刷新后 `anon_id` 不变。
- 新开页面 `session_id` 变化。
- `h5_channel` 能进入每条事件。
- 跑完 24 题可看到完整漏斗事件。
- Vercel、CloudBase 默认域名和本地预览产生的事件可通过 `host` / `origin` 区分。
- 题库或结果文案更新后，事件可通过 `content_version` 区分内容版本。

服务端：

- 非 POST 请求被拒绝。
- 非法事件名被拒绝。
- 超大 payload 被拒绝。
- 批量事件能写入数据库。
- 返回成功和失败状态清晰。

数据：

- 能导出事件明细。
- 能按 `session_id` 还原单次用户路径。
- 能计算首页开始率、完成率、每题流失率、分享意图率。
- 能按 `channel` 比较不同渠道效果。

## 14. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| CloudBase 默认域名 `attachment` 问题未解决 | 用户打不开或异常下载 | 不把默认域名作为用户入口；当前预览走 Vercel，正式传播等待已备案自定义域名 |
| 用户关闭页面导致事件丢失 | 完成/分享事件漏记 | 使用 `sendBeacon`，关键事件立即 flush |
| 网络失败 | 数据不完整 | 本地队列重试，失败不阻塞体验 |
| 数据量突然变大 | 云函数/数据库压力 | 限制单次条数和 payload 大小，pre 阶段先够用 |
| 重复上报 | 指标虚高 | `event_id` 去重，聚合时按 session 去重 |
| 埋点侵入业务代码 | 后续难维护 | 独立 `analytics.mjs`，`app.mjs` 只保留事件调用 |

## 15. 后续代码接入边界

允许改：

- `src/analytics.mjs`
- `src/app.mjs` 中的埋点调用和耗时记录
- `tests/analytics.test.mjs`
- CloudBase 云函数目录
- 部署文档中的埋点配置说明

不应改：

- 题库结构。
- 结果配置结构。
- 内部打分逻辑。
- 分享图业务闭环。
- 页面用户可见文案口径。

如需要修改用户规则说明中的隐私文案，应保持“匿名统计、不采集真实身份”的边界。

## 16. 内容版本维护

当前内容版本：

```text
content-2026-05-28-gpti-title-clean-a
```

需要递增 `contentVersion` 的情况：
