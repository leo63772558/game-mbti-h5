# 异界开局人格测试 H5 数据看板与汇总方案

## 1. 目标

本方案最初落地 P0 数据看板，继续保持用户侧 H5 为纯静态页面，不引入 React / Vue / Next / Vite，不改题库、打分逻辑和结果配置结构。

2026-05-22 状态更新：Phase 5B 已在代码层把 `analytics_source_daily` 升级为来源看板快照表。有 `host` / `contentVersion` 筛选时，核心指标、漏斗、题目、结果和分享明细都从该来源快照生成；后台页面仍只调用 `dashboard_api`，不直接读取 `analytics_events`。

2026-06-10 评分校准补丁：当前内容版本为 `content-2026-06-10-gpti-scoring-calibration-a`。本版本在 `content-2026-06-05-gpti-side-quest-c` 基础上校准题目 `poles`，降低选项位置导致的结果偏置；最终 16 型结果名称、统计口径和 CloudBase 看板聚合方式不变。问卷提交数、QQ群新增人数和群内讨论质量属于外部承接数据，不进入当前 CloudBase 看板。

2026-05-28 标题清洁补丁：当前内容版本为 `content-2026-05-28-gpti-title-clean-a`。本版本在 2026-05-27 GPTI 兜底正式文案基础上清理题目标题编辑分隔符；GPTI `question_answer` 仍使用 `option_id: a/b/c/d`、`keywords` 和 `poles`；旧 `content-2026-05-21`、`dimension`、`score_*` 仅用于历史兼容。第一阶段不新增关键词热度、四轴分布或隐藏特质分布统计。

看板只服务运营和技术复盘，核心回答：

1. PV / UV / session 数。
2. `test_start`、`test_complete` 和完成率。
3. 从入口到分享行为的关键漏斗。
4. 每题曝光、答题数、答题率、平均耗时、选项分布。
5. 结果类型分布、占比、平均 confidence。
6. 分享行为和平台偏好。

## 2. 架构

采用低成本链路：

```text
analytics_events 明细表
  -> analytics_rollup 云函数按天聚合
  -> 聚合表
  -> dashboard_api 只读聚合表
  -> admin/dashboard.html 纯静态后台页面
```

边界：

- `admin/dashboard.html` 不直接读取 `analytics_events`。
- `dashboard_api` 不返回 `anon_id`、`session_id`、完整 `payload` 等明细隐私字段。
- `analytics_rollup` 是唯一扫描明细表的组件。
- `analytics_rollup` 只由 CloudBase 控制台手动触发或定时器触发，不在页面上暴露手动刷新按钮。
- 日期口径统一为 `Asia/Shanghai` 自然日。
- 聚合结果同时写 `all` 总览和每个 `channel` 分渠道。
- 默认排除测试渠道：`e2e_*`、`debug_*`、`test_*`。
- 来源筛选支持按 `host` / `contentVersion` 筛选，读取 `analytics_source_daily` 来源快照表。
- `origin` 仍只保留在 `analytics_events` 明细中，Phase 5B 不提供 `origin` 筛选。
- 无来源筛选时，核心指标、漏斗、题目、结果和分享明细仍按原 5 张 `date + channel` 聚合表汇总。
- 有来源筛选时，核心指标、漏斗、题目、结果和分享明细均按 `date + channel + host + content_version` 口径汇总。
- 当前 GPTI 第一版仍为 24 题，漏斗节点 `1 / 8 / 16 / 24` 暂时保持不变。

### 2.1 上线入口与数据口径

当前所有预览、手机验证和临时试玩入口放在 Vercel，主要 host 为 `demo-phi-pearl.vercel.app`。CloudBase 默认静态托管域名已观察到 `Content-Disposition: attachment`，只作为技术排查入口，不作为正式用户入口。

正式用户入口等待腾讯光核后期提供已备案正式域名。正式域名接入后，需要把该域名加入 CloudBase 安全域名和 `analytics_collect` CORS allowlist，并在真实浏览器中验证 `/analytics/collect` -> `analytics_rollup` -> `analytics_source_daily` -> `dashboard_api` -> `admin/dashboard.html` 全链路。

`phase5a_browser_0522`、`phase5b_browser_YYYYMMDD` 等渠道是上线前验证数据，不是真实运营数据。正式运营看板应优先按正式域名 `host` 和当前 `contentVersion` 筛选；Vercel host 继续用于预览、回归和回滚观察。GPTI 当前筛选版本为 `content-2026-06-10-gpti-scoring-calibration-a`。

## 5. analytics_rollup 调用

默认聚合今天和昨天：

```json
{}
```

```json
{
  "from": "2026-05-20",
  "to": "2026-05-20"
}
```

临时包含测试渠道：

```json
{
  "from": "2026-05-20",
  "to": "2026-05-20",
  "includeTest": true
}
```

建议环境变量：

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `ROLLUP_MAX_DAYS` | `31` | 单次最大聚合天数 |
| `ROLLUP_PAGE_SIZE` | `1000` | 明细分页读取条数 |
| `ROLLUP_MAX_SOURCE_EVENTS` | `50000` | 单次最大扫描事件数 |

## 6. dashboard_api

请求：

```http
GET /dashboard/summary?from=2026-05-20&to=2026-05-20&channel=all
Authorization: Bearer <DASHBOARD_TOKEN>
```

来源筛选请求：

```http
GET /dashboard/summary?from=2026-05-27&to=2026-05-27&channel=all&host=demo-phi-pearl.vercel.app&contentVersion=content-2026-06-10-gpti-scoring-calibration-a
Authorization: Bearer <DASHBOARD_TOKEN>
```

返回：

```json
{
  "ok": true,
  "range": {
    "from": "2026-05-20",
    "to": "2026-05-20",
    "channel": "all",
    "host": "",
    "contentVersion": "",
    "timezone": "Asia/Shanghai"
  },
  "summary": {},
  "source_summary": {},
  "funnel": [],
  "questions": [],
  "results": [],
  "share": {},
  "daily": {
    "summary": []
  },
  "source_daily": {
    "summary": []
  },
  "meta": {
    "source": "aggregates",
    "summary_scope": "date_channel",
    "detail_tables_scope": "date_channel",
    "uv_scope": "daily_exact",
    "excluded_channel_prefixes": ["e2e_", "debug_", "test_"],
    "last_rollup_at": "2026-05-20T12:00:00.000Z"
  }
}
```

当请求包含 `host` 或 `contentVersion` 时：

- `summary` 使用 `analytics_source_daily` 聚合后的核心指标。
- `funnel`、`questions`、`results`、`share` 均由 `analytics_source_daily` 内嵌快照合并生成。
- `meta.summary_scope` 为 `source_daily`。
- `meta.detail_tables_scope` 为 `source_daily`。
- 如果命中的是 Phase 5A 旧 summary-only 来源记录，API 不 fallback 到未筛选明细，而是返回空明细并通过 `meta.source_detail_coverage` 标记 `missing` 或 `partial`，提示需要重新执行 rollup 回填。

权限：

- `DASHBOARD_TOKEN` 放在云函数环境变量。
- 前端页面只提供输入框，不写死 token。
- token 错误或缺失时返回 `401`。

浏览器跨域注意：当前后台页面请求带 `Authorization`。如果后续改为正式域名、同源路由或新增来源域名，`dashboard_api` 的 CORS 响应与 allowlist 需要单独确认后再改，不在 GPTI 第一阶段顺手修改。

建议环境变量：

| 变量 | 默认值 | 说明 |
|---|---:|---|
| `DASHBOARD_TOKEN` | 无 | 必填，看板访问 token |
| `DASHBOARD_MAX_DAYS` | `31` | 单次查询最大天数 |
| `DASHBOARD_PAGE_SIZE` | `1000` | 聚合表分页读取条数 |

## 7. 资源点控制

- 用户侧继续批量上报，减少云函数调用次数。
- 看板页面只调 `dashboard_api`，不读明细表。
- `dashboard_api` 无来源筛选时只读原 5 张聚合表；有 `host` / `contentVersion` 筛选时只读 `analytics_source_daily`。
- `analytics_rollup` 默认只扫 2 天，手动最大 31 天。
- 默认查询当天，必要时查询最近 7 天。
- 测试渠道默认排除，避免 e2e 数据污染报表。
- 聚合表不保存匿名 ID、会话 ID 和完整 payload。
- Phase 5B 不扩展原 5 张聚合表主键维度，也不新增来源明细集合；通过扩展 `analytics_source_daily` 内嵌快照控制集合和索引数量。
