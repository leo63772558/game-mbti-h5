# 结果卡分享闭环下一阶段说明

## 1. 背景

当前“游戏 MBTI H5”已经完成“异界档案局”第一阶段视觉骨架和第二阶段部分轻动效：

- 首页已升级为“异界档案终端”气质。
- 答题页已有档案面板、冷青与旧金体系、选项级联出现、选中点亮反馈。
- 章节反馈页已有“封存”印章感觉。
- 生成页已改成三行状态依次点亮。
- 结果页已升级为“异界职业档案卡”，有编号、水印、稀有度、实体卡质感和扫描成像感。

> 2026-05-19 状态更新：本文件原本是“下一阶段说明”，其中大部分分享闭环已经落到当前代码。旧示例中出现的 `保存结果卡`、`#MBTI` 或内部类型编码不再作为当前用户端口径，当前实现以 `生成分享图`、平台文案复制、`ARCHIVE-024` 等游戏化表达为准。

最近一次修复了“点击选项后闪一下再进入下一题”的问题。根因是点击选项后当前题会先重渲染以显示选中态，而 `.choice-enter` 和 `.screen-enter` 入场动画被重新触发，导致选项 opacity 从 1 回到 0。当前修复方式是：已作答题加 `quiz-answered` class，并在 CSS 中禁用这次重渲染的页面/选项入场动画。

下一阶段建议重点做“结果卡导出与平台分享闭环”，不要急着继续加视觉装饰。

## 2. 当前必须保持的边界

继续保持：

- 纯静态 H5。
- 不引入 React / Vue / Next / Vite。
- 不引入构建链。
- 不破坏现有题库/结果配置工作流：
  - `src/data/questions.mjs`
  - `src/data/results.mjs`
  - `assets/results`
  - `assets/avatars`
  - `assets/og`
- 不改四维打分逻辑，除非先补测试。
- 移动端优先，PC 端居中手机画布。
- CSS 动效只用 `transform` / `opacity`，避免微信内置浏览器卡顿。
- 改完必须跑：

```powershell
node --test .\H5\demo\tests\*.test.mjs
```

## 3. 下一阶段核心问题

历史问题：结果页按钮曾是“保存结果卡”，点击后直接下载 SVG。

这不适合 H5 传播，因为用户没有看到最终将要分享的图片，也缺少平台化分享路径。当前已调整为：

1. 先生成并弹出一张可预览的结果分享图。
2. 用户确认图好看后，再选择保存图片、复制平台文案或复制拉人链接。
3. 分享图本身包含结果信息和回流入口，适合微信朋友圈、小红书、B站动态、小黑盒等场景。

## 4. 外部案例和启发

已查到的近期公开 H5 案例启发：

- 小红书 2025 H5「你深夜到底在小红书刷什么？」最后会生成带二维码的活动海报，而不是只给一个下载按钮。启发：结果图要承担截图传播和回流入口。参考：https://www.h5anli.com/cases/202510/wxsvg.html
- 腾讯新闻 2025「年画有解法」提供带活动二维码的年画和无二维码壁纸两类保存图。启发：后续可以区分“传播版档案卡”和“纯壁纸版档案卡”。参考：https://www.h5anli.com/cases/202501/nianhua.html
- 多数营销 H5 的终点不是普通网页分享，而是“生成海报 + 长按保存 + 二维码/链接回流”。启发：结果海报比普通链接更适合作为朋友圈、小红书和社区动态里的传播物料。

技术约束：

- Web Share API 可以唤起系统分享面板，但不能稳定指定分享到微信朋友圈、小红书、B站或小黑盒。
- 微信 JS-SDK 自定义分享需要公众号权限、JS 安全域名和签名服务；这会破坏当前纯静态架构。
- 现阶段不要承诺“一键分享到某个平台”。更稳的产品表达是“去小红书晒图”“发 B 站动态”“发小黑盒”，点击后完成保存图或复制文案，并给出操作提示。

## 5. 建议信息架构

结果页不要直接下载，改成：

- 主按钮：`生成分享图`
- 次按钮：`复制分享文案`
- 次按钮：`重新测试`

点击 `生成分享图` 后出现弹层：

- 顶部：`分享档案已生成`
- 中部：竖版分享图预览
- 底部三个主操作：
  - `保存图片`
  - `去平台晒图`
  - `复制测试链接`

`去平台晒图` 再打开平台面板：

- 微信朋友圈
- 小红书
- 哔哩哔哩
- 小黑盒
- 通用分享

每个平台项的行为建议：

- 微信朋友圈：提示“保存图片后，点右上角分享到朋友圈”，同时复制适合微信的短文案。
- 小红书：保存图片或提示长按保存，复制小红书风格标题/正文/标签。
- 哔哩哔哩：复制动态文案，提示上传图片发动态。
- 小黑盒：复制玩家社区口吻文案，提示上传图片。
- 通用分享：优先调用 `navigator.share()` 分享链接；如果不支持，则复制链接。

## 6. 分享图内容建议

分享图建议先做 PNG / Canvas 版本，不再把 SVG 下载暴露给用户。

画布比例建议：

- 首选：`1080 x 1600`
- 兼容手机截图：竖版 2:3 左右
- 预览弹层中等比缩放，不能超出 390px 宽手机视口

分享图必须包含：

- 顶部档案条：`异界档案局 / ARCHIVE 24`
- 稀有度：如 `SSR 临时档案`
- 档案编号：如 `NO. ESTP-24`
- 结果类型与身份：如 `ESTP | 冲锋赌徒`
- 结果名：如 `上头战神`
- 判决金句
- 3-5 个标签
- 简短“玩家翻译”或“系统罪状”
- 测试入口文案：`扫码生成你的游戏灵魂职业`
- 二维码或短链占位
- 渠道参数或来源标记，可从 `h5_channel` 生成不同回流链接

不要在本阶段做：

- 复杂 3D。
- 视频背景。
- 需要服务端的短链生成。
- 真正一键发布到第三方平台。

## 7. 技术实现建议

优先小步实现：

1. 新增结果分享弹层 DOM。
2. 先用 Canvas 生成 PNG data URL。
3. 弹层展示 `<img>` 预览。
4. `保存图片` 使用 `<a download>` 触发下载。
5. 如果下载能力不稳定，显示“长按图片保存”的提示。
6. 平台分享先做“复制文案 + 操作提示”，不要写死不可用的第三方跳转。
7. `navigator.share()` 只作为通用分享增强能力，并且必须 feature detect。

可能涉及文件：

- `src/app.mjs`
  - 结果页按钮结构
  - 分享弹层状态
  - 平台文案复制
  - Canvas 生成入口
- `src/styles.css`
  - 分享弹层、预览图、平台面板样式
- `src/share.mjs`
  - 建议新增 `buildPlatformShareText`
  - 建议新增或改造 `buildResultCanvasImage`
  - 现有 `buildResultSvg` 可保留为 fallback
- `tests/share.test.mjs`
  - 补平台文案测试
  - 补链接保留渠道参数测试
