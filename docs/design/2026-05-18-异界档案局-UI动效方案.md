# 异界档案局 UI 动效方案

## 1. 定位

本方案用于“游戏 MBTI H5”的首版视觉升级。目标不是把项目改成复杂框架，而是在现有纯静态 H5 上，把问卷感改造成“异界系统读取选择并生成职业档案”的沉浸体验。

> 2026-05-19 状态更新：本文件保留首版 UI/动效方案的设计背景；实际实现已进入“生成分享图 + 平台文案闭环”版本。下面涉及 `INTJ 型玩家`、`保存结果卡` 等旧示例时，应按当前实现理解为历史草案，用户端继续使用“档案编号 / 职业谱系 / 游戏灵魂职业”等游戏化口径。

核心体验：

- 用户不是在做题，而是在被异界档案局记录选择。
- 24 题是一次档案采样流程。
- 结果页是一张可保存、可传播的游戏灵魂职业档案卡。

## 2. 设计关键词

- 档案
- 契约
- 扫描
- 职业卡
- 异界系统
- 轻冒犯
- RPG 开局

视觉参考可以借鉴 SBTI 的清晰测试结构，但不照搬它的浅绿问卷风。SBTI 的价值在于信息层级清楚、开始路径直接、模型说明可信；本项目需要在此基础上强化游戏感和传播卡片感。

## 3. 视觉系统

### 3.1 色彩

基础色：

- 深夜黑：`#0d1019`
- 面板黑：`#191d2e`
- 冷青：`#7be0d6`
- 旧金：`#c7a96b`
- 正文米白：`#f6f0e4`
- 次级灰紫：`#8f96ad`

使用原则：

- 深色背景负责沉浸感。
- 冷青负责系统扫描、选中态、交互反馈。
- 旧金负责稀有度、档案编号、章节印章。
- 不使用高饱和霓虹紫蓝，不做大面积炫光。

### 3.2 材质

页面材质：

- 半透明档案面板。
- 1px 细边框。
- 极弱内描边。
- 轻微背景纹理或扫描线。
- PC 两侧背景可保留暗色空间，不扩展成宽屏网站。

结果卡材质：

- 类似异界身份证 / 职业档案。
- 有编号、稀有度、水印、职业名、判决金句。
- 卡片边框可使用冷青和旧金的双层细线。

### 3.3 字体与排版

继续使用系统中文字体，避免加载外部字体增加首屏成本。标题通过字重、尺寸、字间距和边框元素建立气质。

排版原则：

- 移动端优先。
- 最大内容宽度保持约 440px。
- PC 端居中手机画布。
- 标题不压迫首屏，确保 CTA 可见。
- 每屏只给一个主任务。

## 4. 页面设计

### 4.1 首页

首页像进入“异界档案终端”。

结构：

- 顶部档案条：`ARCHIVE 24` + 当前 `h5_channel`
- 主标题：`异界开局人格测试`
- 副标题：`24 题生成你的游戏灵魂职业`
- 开场文本：保留现有异界醒来文案
- 主按钮：`开始冒险` / 有进度时 `继续冒险`
- 次按钮：`查看规则`

建议增加的视觉：

- 背景暗纹：地图线、档案网格、低透明扫描线。
- 主面板轻微入场：上移 8px + 透明度 0 到 1。
- CTA 按下反馈：轻微下压。

### 4.2 规则弹窗 / 规则页

规则不做成普通说明书，而做成“档案局免责声明”。

内容重点：

- 娱乐向游戏人格测试。
- 共 24 题，约 3-5 分钟。
- 本地计算，不上传敏感数据。
- 结果适合保存和分享。

视觉：

- 面板标题使用 `档案局说明`。
- 列表前缀使用短横或细节点，不使用复杂图标。

### 4.3 答题页

答题页是一屏一个“命运分歧记录”。

结构：

- 章节名
- 题号：`07 / 24`
- 四段式章节进度
- 题干
- 5 个选项
- 上一题 / 下一题

选项设计：

- 左倾向和右倾向的强度通过前缀表达：`坚定选择`、`比较偏向`、`先观察一下`。
- 选中后边框冷青或旧金点亮。
- 点击后停顿 300-500ms 自动进入下一题。

动效：

- 新题进入：整体淡入 + 轻微横向移动。
- 选项进入：短延迟级联出现。
- 选中反馈：边框点亮 + 背景明度提升。

性能边界：

- 只动画 `opacity` 和 `transform`。
- 不监听滚动。
- 不引入重型动画库。

### 4.4 章节反馈页

每 6 题出现一次，降低疲劳并制造仪式感。

结构：

- `CHAPTER 1`
- 章节反馈文案
- 辅助文案：档案正在变厚、继续往前走
- 按钮：`继续冒险`

动效：

- 章节符文点亮。
- 档案印章落下感：用 scale + opacity 模拟。
- 背景扫描线扫过一次。

### 4.5 生成页

生成页不要只用 spinner，而是三段式读取。

文案：

- `正在读取你的 24 次选择`
- `正在比对异界职业谱系`
- `正在生成你的游戏灵魂职业`

动效：

- 三行依次点亮。
- 右侧可显示短横闪烁或扫描点。
- 总时长约 1.6-2.4 秒。

异常状态：

- 超过 8 秒时显示 `重新生成`。
- 首版可以先保留现有自动跳转逻辑，后续再补超时按钮。

### 4.6 结果页

结果页是传播核心。

结构：

- 稀有度：如 `SSR 临时档案`
- 类型与身份：如 `职业谱系 04 | 终局策士`
- 头像或职业视觉
- 大名：如 `PLAN-B 预案怪`
- 档案信息：`ARCHIVE-024 · 终局策士`
- 判决金句
- 标签
- 异界身份
- 玩家翻译
- 系统罪状
- 隐藏天赋 / 致命弱点 / 适配队友 / 天敌队友
- 置信度
- 生成分享图 / 复制分享文案 / 重新测试

视觉：

- 结果卡是实体卡，不是普通内容卡。
- 卡面保留水印和编号感。
- 可添加轻微反光扫过，但只播放一次或低频播放。

保存/分享：

- 按钮文案统一为 `生成分享图`。
- 当前已优先使用 Canvas/PNG 生成分享图，并保留 SVG fallback。
- 保存动作放在分享图预览弹层中，移动端同时提示长按保存。

## 5. 动效清单

首版建议实现：

1. 页面入场淡入。
2. 首页背景低速扫描线。
3. 选项点击点亮。
4. 选项级联出现。
5. 章节印章出现。
6. 生成页三行状态依次点亮。
7. 结果卡扫描成像。

暂不实现：

- 复杂 3D。
- 粒子爆炸。
- 滚动视差。
- 大面积视频背景。
- 需要第三方动画库的复杂交互。

## 6. 技术边界

继续保持纯静态 H5。

允许修改：

- `src/styles.css`
- `src/app.mjs` 中少量结构 class 和状态文案
- `index.html` 中 SEO/OG meta

保持配置化：

- 题库仍在 `src/data/questions.mjs`
- 结果仍在 `src/data/results.mjs`
- 结果图仍在 `assets/results`
- 头像仍在 `assets/avatars`
- OG 图仍在 `assets/og`

不引入：

- React / Vue / Next.js
- 构建链
- 服务端接口
- Vercel 专属能力

## 7. 迁移友好原则

本设计必须能迁移到腾讯云 COS、腾讯云 CVM + Nginx 或其他静态托管。

要求：

- 所有资源使用相对路径或可替换的绝对生产 URL。
- 不依赖 Vercel Functions。
- 不依赖运行时环境变量。
- 不依赖服务端渲染。
- `index.html` 可作为静态网站入口。

## 8. 验收标准

视觉验收：

- 首页 3 秒内看懂是“异界游戏人格测试”。
- 移动端首屏能看到标题、引子和开始按钮。
- PC 端仍是居中的手机 H5 画布。
- 答题页没有普通表单感。
- 结果卡适合截图分享。

交互验收：

- 24 题流程顺畅。
- 章节反馈不打断体验。
- 返回上一题可用。
- 刷新后进度恢复。
- 生成分享图、保存图片、平台文案复制和复制测试链接可用。

技术验收：

- `node --test .\H5\demo\tests\*.test.mjs` 通过。
- 移动端无横向滚动。
- 微信内置浏览器能打开。
- 线上三个渠道参数可访问：
  - `?h5_channel=wechat_group`
  - `?h5_channel=friend_circle`
  - `?h5_channel=xiaohongshu`

## 9. 分阶段实现建议

第一阶段：视觉骨架

- 背景、面板、按钮、进度条、结果卡样式升级。
- 不改核心逻辑。

第二阶段：轻动效

- 页面入场。
- 选项级联。
- 章节印章。
- 生成页状态点亮。

第三阶段：传播增强

- 正式 OG 图。
- 结果卡 PNG/Canvas 导出。
- 结果卡水印、编号、二维码或短链位。

第四阶段：真机调优

- 微信内置浏览器。
- iPhone Safari。
- Android Chrome。
- 小红书内打开。
